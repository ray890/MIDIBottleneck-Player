# Technical reference

## Parsing and event representation

The parser supports Standard MIDI File format 0 and synchronous format 1 with PPQN time division, either as a bare SMF or inside a RIFF/RMID `data` chunk. RIFF sizes, form type, chunk lengths, odd-byte padding, and the payload boundary are validated before the enclosed `MThd` stream enters the ordinary parser. The payload is a bounded view over the source file rather than an unbounded copy. The parser expands running status, preserves stable track/event ordering, assembles tempo changes into one map, and converts each dispatchable event to an intended microsecond timestamp.

Running status normally ends at metadata and SysEx boundaries. One compatibility case is shared by preflight, production, and the reference parser: when the first message after metadata begins with data and the most recent channel status is the only deterministic valid interpretation, that status is restored and the repair is counted. This does not permit status recovery after SysEx, without a prior channel status, or through a malformed/truncated channel message.

Playback and Analysis consume `IMidiEventStore`, an indexed read-only boundary with exact access and lower-bound search. The production backend stores immutable 40-byte value records in 2,048-record (80 KiB) segments. Ordinary messages retain up to three bytes inline; variable-length SysEx/system payloads use an append-only side store split into 1 MiB byte segments. Final event identity is the indexed store position, while merge-only `Order` and the redundant stored `EventIndex` are absent from final records.

Production readers return a small immutable handle over either the compact backend or the retained list/reference test oracle. Short-message playback, Analysis, seeking, channel-state tracking, source-value lookup, SysEx assembly, and the per-note gate use that handle without constructing one object per event. Analysis has a concrete segment scan so x86 does not pay for large value copies or interface dispatch in its hottest sequential loop.

Production parsing reads each declared track through a 64 KiB boundary-limited stream reader into compact provisional record/payload segments. Tempo changes use 4,096-value segments. A stable tick/track/source-order heap merge advances the exact decimal tempo cursor, assigns timestamps, appends directly to the final compact builder, counts notes, and builds final-index channel-state metadata in the same pass. Consumed provisional record, payload, and tempo segments are released progressively. There is no complete raw-track array, per-event object graph, contiguous merged event list, second timestamp pass, or post-merge conversion stage.

The one-value source chase index stores each monitor attribute history in immutable 4,096-entry segments and performs logarithmic lookup by final event position. Build 32 adds a separate whole-state index with 8-byte `(event index, value)` entries in the same bounded segment size. It has sparse series for controllers, Program, bend, pressure, reset boundaries, selectors, and only the RPN/NRPN parameters that actually occur. Finalization is cancellable and unload releases the song-owned graph.

Whole-state lookup uses the final lower-bound event index, not a time-only approximation. Changes strictly before the target are eligible; changes at the target remain normal playback events. Reset All Controllers retires earlier affected controller, bend, pressure, selector, and parameter state while preserving bank, channel volume, and Program according to the documented MIDI reset practice. Data Entry MSB/LSB is resolved to a 14-bit value; Data Increment/Decrement changes a known selected value by one, while an increment of an unknown receiver value is not guessed.

Chase output is an ordered control batch before any later source event: bank MSB/LSB, Program, other controllers, bend/pressure, sorted RPN then NRPN values, and the final selector. Disabled channels are skipped and forced overrides suppress conflicting chased attributes before pending overrides are applied. Notes, poly pressure, SysEx, system/meta events, and channel-mode commands are absent from the index. Production loading remains bounded by the explicit signed 32-bit event-index identity and aggregate address space/commit, not a greater-than-2-GB array. No release package requires `gcAllowVeryLargeObjects`.

### Large-file preflight

Preflight is architecture-aware and deliberately avoids reading ordinary files twice. The file-size gate uses a conservative 64 bytes of possible peak MIDI-storage expansion per source byte plus a 64 MiB fixed allowance. With warning boundaries of 1 GiB on x86 and 4 GiB on x64, this produces scan thresholds of 15 MiB and 63 MiB respectively. File size selects whether an exact scan is worthwhile; it is never used as the displayed estimate.

The count-only scanner shares the production parser's bounded RMID/SMF view, track reader, VLQ decoder, header validation, channel/system message-length rules, and narrow post-meta running-status repair. It understands meta/tempo events, F0 prefixing, F7 payloads, declared track boundaries, and the same malformed/truncated cases. It allocates no event records, payload copies, tempo histories, or source indexes.

The estimator uses exact event, long-payload, tempo, per-track provisional, per-channel/attribute source-history, note-bearing track/channel, and Bank/Program counts. It models 40-byte records in 2,048-entry segments, 1 MiB payload segments, 4,096-entry tempo/source segments, segment-reference arrays, architecture-sized references/headers, track-bounded merge workspace, and the bounded two-name-per-track retention allowance. The retained projection describes the published song structures. The peak range runs from the larger of completed provisional/final storage to a conservative upper bound where both coexist, plus bounded builder/merge workspace.

The same count-only pass now reports a separate optional Track-routing allowance. It includes the compact one-byte source-event destination map, note-occurrence and patch-timeline summaries, bounded active-occurrence workspace, generated destination-state upper bound, and the routed logical-index view used by Playback and Analysis. It does not construct routed payload copies or a second per-event object graph. Both the loaded-song and optional-routing projections participate in the existing architecture warning and cancellable Continue/Cancel boundary. CLR headers, fragmentation, other program memory, and operating-system behavior make these projections rather than byte-perfect promises.

A compact per-song index records state-changing channel messages for logarithmic one-attribute source-value chase. It is not automatic whole-song state chase.

## Track-routing planner and transformation

The session-only routing unit is `(source track, source MIDI channel)`. Both parsers retain bounded sanitized Track Name and Instrument Name metadata for presentation, while event identity remains the immutable source-store index. Channel-less SysEx/system traffic bypasses routing.

The deterministic planner first identifies note-bearing `(track, channel)` combinations (called profiles internally). Bank, Program, sustain, reset, bend, pressure, and controller state is then evaluated as source-channel-global state, including messages stored in a different format-1 track; note-empty initialized channels do not become musical entries. Profiles retain effective patch history, note occurrences, sustain-extended sounding intervals, dynamic channel state, event/note counts, and dominance. The planner applies validated manual destinations first and reserves destination channel 10 by default for source-channel-10 percussion. Exact-safe and GM-family retain their compatibility-first behavior. Aggressive instead selects destination representatives across all remaining profiles with one deterministic objective balancing dominance, independent same-pitch overlap, channel-state conflicts, distinct patch/family coverage, time overlap, and the cost of retimbrance. Stable track/channel and destination tie-breaks make repeated plans identical.

After representative selection, each remaining Aggressive profile takes its least-cost compatible destination. A profile is omitted only when every merge has the combined destructive overlap/state-conflict threshold and its dominance is below every selected destination representative. The omitted assignment retains its source identity and exact attack count, receives no destination, and therefore suppresses its complete routed note occurrence. It is a valid Aggressive result requiring explicit lossy confirmation, not an unresolved hard error. A complete plan exposes every assigned or omitted MIDI track/channel entry, destination group, representative patch, state conflict, same-key overlap, time handoff, retimbrance, percussion exception, warning, omission count, and unresolved error.

The modal system-menu workflow compiles a complete preview after each capacity, usable-channel, percussion-policy, tier, or manual-destination edit. One MIDI track can appear in multiple rows when it uses multiple channels. Usable-channel captions derive their bold state from the compiled destination set, not from checked order; Patch tooltips reuse the same canonical General MIDI program catalog as Channels and qualify non-GM banks. Manual destinations are seeded into the capacity set before ascending automatic choices, so an out-of-sequence correction replaces rather than adds a melodic destination. Omitted entries use a prominent table state and a separate complete-preview section with note-start counts. The summary defines merged entries as additional track/channel entries sharing an output channel and separately reports routed entries, destinations, retimbrance, omitted entries/note starts, surviving source messages, and generated destination Bank/Program messages. The final source-plus-generated total is asserted against the immutable routed event-store count consumed by both Playback and Analysis. Apply remains disabled while any entry is unresolved, but an otherwise valid omission becomes applicable after confirmation. Any GM-family, aggressive, omitted, or manual assignment marks the compiled route as requiring explicit warning confirmation. The stopped-only MainForm boundary constructs the derived song before unloading the current engine attachment, so wrong-source, invalid, unconfirmed, or failed plans cannot partially replace a working configuration.

An accepted route wraps the original `IMidiEventStore` in one immutable canonical event view. Ordinary musical events rewrite only the channel nibble. Source Bank/Program messages are suppressed and each destination compiles its own deduplicated canonical state transitions before the affected routed note boundary. A single non-overlapping role may hand the destination to its effective Bank/Program state, including later instrument changes; real overlap restores or retains the destination representative and suppresses losing changes. Generated state has a contiguous routed index but no false source-event identity, while every surviving source event retains its original source-store index, time, track, order, and payload identity. Unused-channel initialization is omitted. A source channel whose other global state would require multiple destinations is rejected explicitly. Playback, Analysis, source-state lookup, whole-state chase, queue/gate occurrence pairing, destination filtering, forced overrides, Channels readouts, and statistics all consume the same derived `MidiSong`. Clearing the route restores the original song; unload/file replacement clears the session plan. Playing and Paused states disable the planner command and the application boundary independently rejects active changes.

## Scheduler and timing

A dedicated above-normal-priority worker uses `Stopwatch` as the monotonic transport clock. A Windows waitable timer handles coarse waits; only the short final interval uses yield/spin checks.

The direct Events/sec model uses one generation-owned rational service clock. Each service start adds 1,000,000 microseconds to an integer numerator, divides by the selected rate, and carries the remainder. This produces exact long-run rates without floating-point drift or a rounded reciprocal, including 1,000,001–9,999,999 events/sec where some individual service durations are zero microseconds. Rejected arrivals and pending entries consume no phase; Clear or a newly applied filter rolls back an in-service quantum when that source event is retired. Playback, forward-only admission, and Analysis use the same rule. A selected rate of zero follows the immediate-service path. Changing from a rate above one million to whole-microsecond Processing time necessarily chooses the nearest representable whole-microsecond setting; it does not silently alter the still-selected Events/sec value.

Ordinary rate-model and live value edits publish one immutable mode/value snapshot. The worker reads it at the next service start. A current service quantum and already scheduled virtual completions retain their old durations; pending events retain their order. A new snapshot resets the Events/sec fractional remainder to zero at that next start. The immediate path checks for edits between sends and returns to admission when the model changes. Per-note interval changes still use their separate safety restart because they alter pending pitch decisions.

Immediate dispatch returns to admission/statistics publication after at most 2,048 sends or about 8 ms of completed output work. Those checkpoints add no deliberate sleep and preserve payload/order exactly. Stop and default Pause/Seek are observed before the next send after any blocked native call returns. In optional preserving mode, the in-service logical event or simultaneous batch finishes before the worker parks or begins draining its already admitted decisions.

The scheduler is the sole ordered writer to output state. UI control requests—overrides, one-value chase, mute safety, and output restarts—cross the same serialized boundary rather than calling native output concurrently. A monotonic wake generation closes the race between signalling the manual-reset wake event and the worker resetting it, so a control request cannot sleep until the next source event merely because those operations crossed. After a forced send returns, its observed value is published as current only if that same force is still requested; a concurrent Auto or replacement request leaves the wire value historical until the newer boundary succeeds.

Opening Channels during active or paused playback, when automatic state chase is enabled, queues an indexed source-state restoration at that same ordered boundary. The optional monitor starts with a gray source-index fallback; each successful restoration send is recorded as observed channel state without increasing source Sent, polyphony, or output-position counters. Failed or retired requests preserve historical provenance and report non-modal feedback. The batch excludes disabled channels and attributes superseded by forced overrides. Re-activating an open monitor creates no new request, and a stopped monitor remains source-historical rather than calling output directly from the UI thread.

## Queue semantics

The unlimited queue uses contiguous indices into the sorted event store, so backlog does not allocate one queue node per event. Finite queues use explicit admission and overflow decisions. Occupancy includes the event in service.

The ordinary event-count capacity is an atomic live setting. Retained finite admission reads it for every arrival instead of capturing a startup copy. A decrease never retracts the in-service item or pending accepted work; new arrivals apply the current overflow policy against the new capacity until the ordered backlog falls within the selected limit. An increase is visible at the next decision. Waiting-time values and overflow policy retain their existing live boundaries. The enabling checkbox, event-count/waiting-time choice, forward-only choice, preserving Pause/Seek, and chase structure remain start/restart settings.

`Drop incoming complete notes` tracks channel/key occurrences in fixed-size state. A rejected NoteOn’s paired NoteOff is suppressed; a NoteOff protecting an already sent note is retained. Protected events and non-note messages can make the configured capacity a soft ceiling, and statistics/pressure include that excess.

`Drop oldest complete note` is a separate finite delayed-queue policy. Pending source events occupy reusable value nodes in 256-node segments, linked both in service order and in eligible unsent-attack order. A pending NoteOff links to its FIFO-matched attack by channel/pitch; an overflow unlinks the oldest eligible attack and its pending release in O(1), with no scan proportional to queue length. The note index is built once from the current pending queue if this policy is selected during playback, then maintained incrementally; other policies need only the service-order links. A later matching release is suppressed when it arrives. An attack entering service leaves the eviction index before any native send, so a release needed for a potentially sounding note remains safe. An incoming release paired with the attack selected for eviction is suppressed in that same decision. Each removed source event increments the ordinary queue-drop counter when actually removed.

If no eligible attack exists, an incoming attack or ordinary non-note source event is rejected explicitly. NoteOffs, sustain-off, and channel-mode safety controls are admitted as protected traffic; these can raise occupancy above the configured soft limit. The excess is counted in queue/pressure statistics. Occurrence FIFO state follows only unmatched source notes; freed pending nodes are reused, and neither Playback nor Analysis builds a per-file note-object graph. Static Analysis uses the same queue/occurrence primitives and exact service calculation, but remains a projection of the unfiltered immutable source file rather than live mutes or overrides. Source filtering runs before finite-queue admission in live playback.

Finite policies without complete-note eviction now use a segmented value FIFO: 256 `Entry` values per reusable segment. Complete-note eviction alone enables the linked value-node and attack/release index. A live policy change converts the pending entries once at the ordered boundary; ordinary admission and overflow never scan the queue. A bounded 120,000-event synthetic comparison found the shared linked-node path slower than the pre-Build-35 implementation for older policies. The FIFO path recovered most of that overhead, with identical projected drop/occupancy decisions and no Gen0 collections in the measured loops; it did not establish full performance parity across machines or workloads.

Muted channel events and source attribute changes conflicting with forced overrides are filtered before scheduler admission. They consume no simulated service, queue space, output rate, or sent count and are reported separately from overflow drops. An event already executing inside a native call cannot be recalled.

Live queue statistics use one shared due-work measurement for None, ordinary queues, Per-note, and Delayed NoteOff. It combines the in-service native call, already accepted structural work, eligible source events that are due but not yet dispatched, and a structural transition only after its logical deadline. A blocked synchronous output cannot advance the worker, so snapshots use the worker's published admission cursor and a lower-bound time search. With active channel/override filters, the immutable candidate range is evaluated once and cached/extended while that cursor is unchanged; ordinary UI refreshes do not rescan the same large blocked range. Filtered, coalesced/rejected, deliberately future, and already-counted structural work is excluded. Static Analysis does not invent unknown native-provider blocking.

The optional forward-only model is a bounded service-duration queue used only for admission and pressure. It shares `ForwardDropQueue` with static Analysis. Accepted MIDI is dispatched immediately and virtual service never delays the worker. Drop newest rejects only the current arrival. Drop incoming complete notes uses the same FIFO note-pair tracker and preserves safety/non-note admissions, so the configured limit remains soft. Both oldest-removal policies and clear/catch-up are rejected in this mode because their target may already have reached native output. Actual backlog and virtual occupancy have separate snapshot fields and presentation.

Build 42 adds an alternative finite-queue limit measured in microseconds. The scheduler compares the logical source time at admission with the oldest eligible pending event; strict `age > limit` overflow means equality is permitted. In-service native output is never removed. Drop oldest dequeues until the condition is repaired. Drop oldest complete note may evict only when its indexed attack is the queue head, so every such eviction monotonically reduces overdue pressure; protected releases and safety controls make this an explicit soft limit. Clear/catch-up retains its existing ordered reset boundary. Playback and Analysis share the same comparison, policy eligibility, complete-note pairing, and drop accounting. Per-bucket peak age drives Analysis pressure while the report retains both age and occupancy evidence.

Waiting-time mode uses independent remembered limits and policies and is mutually exclusive with forward-only admission. Drop newest and Drop incoming complete notes are omitted because rejecting a new arrival cannot repair an already overdue head. The public UI range is 1–1,800,000,000 microseconds; the upper bound stays within the shared numeric editor while covering thirty minutes of modeled waiting. Queue-age snapshots include pending work plus newly due eligible source events accumulated behind a blocked synchronous send. The filter cache also retains the first eligible index, so muted and override-suppressed events cannot become the reported oldest waiter and unchanged UI refreshes do not rescan a giant range.

The forward-only choice is captured at playback start. Its system-menu command is disabled while Playing or Paused; toggling it never changes the interpretation of an existing queue. The grouped Rate model selector maps explicit choices to service modes; its headings are not enum values. None has no simulated service, an ordinary choice normally means delayed service, and an ordinary choice plus a finite queue and the checked forward-only option means virtual admission without delayed output. Selecting None from active forward-only admission unchecks that option. Direct ordinary-to-ordinary model changes publish one live service-clock configuration; structural changes to or from None or Per-note gating stop the old worker before publishing the new configuration and restarting at the same position. Static Analysis projects virtual pressure and forward drops from immutable source/configuration data, but explicitly does not claim to predict blocking inside a driver or synthesizer.

The live per-note interval gate separates source-note identity from constrained output state. Source NoteOffs pair FIFO with NoteOns from the same track/channel/pitch, with an oldest-same-channel fallback for unusual cross-track files. Simultaneously unmatched occurrences live in reusable 4,096-entry segments allocated on demand; memory therefore follows peak overlap rather than total file size, and freed entries are reused. Allocation failure is surfaced as an explicit playback failure instead of falling back to lossy track-blind pairing. Each output pitch stores only Up/Down plus the channel of the NoteOn actually sent.

Delayed NoteOff is a separate structural mode with one shared Playback/Analysis state machine for each of the 128 pitches across all tracks and effective output channels. `D` is measured from the emitted attack and supplies both its minimum duration and earliest retrigger eligibility. Every emitted natural or retriggering NoteOff begins `R = min(floor(D / 4), 40,000 µs)` of derived experimental recovery; `D = 0` gives `R = 0` and adds no positive-duration timing boundary or time quantization.

An attack at `t < attack emission + D` and its paired release are coalesced. At or after that boundary, a competitor may displace a held owner: the old owner's actual-channel NoteOff is emitted first, then at most one still-supported candidate is emitted when recovery ends. That single per-pitch recovery candidate is bounded ownership state, not an interval-created FIFO or a general following-batch queue; contenders replace or lose to the one slot through the short `R` window. Recovery candidates reuse Per-note's velocity-first, stable-source tie-break. Releases from displaced, coalesced, losing, or ended candidates cannot release a later owner. Sustain may keep a released candidate eligible until pedal release. Source release encoding is retained where applicable. Segmented occurrence storage is capped at 1,000,000 live entries and reused; lifecycle hard boundaries clear ownership and recovery state.

The optional adaptive note-traffic clock is one shared Playback/Analysis component used by Per-note and Delayed NoteOff. Its session check can be changed under any stopped Rate model; non-applicable models ignore it and a later musical-gate selection consumes the retained value. A logical boundary remains open through every deterministic resolution pass at that timestamp; after it completes, the clock counts only actual emitted NoteOn and NoteOff messages and advances by saturated `D * max(1, N)`. Synthesized retrigger releases and replacement attacks count. Filtered/coalesced candidates, losing owners, channel-mode and ordinary non-note traffic do not. Delayed local duration/recovery remains an earliest-due constraint, so adaptive waiting can postpone due work but cannot emit it early. Hard lifecycle/safety boundaries bypass the clock and discard its state.

Both musical gates use a zero-queue rule for backlog generated solely by their own interval pacing: deterministic pitch candidates may occupy only the logical batch currently being resolved. Untransmitted attacks are discarded with their paired releases rather than retained for another gate interval. Delayed NoteOff's one candidate per pitch may remain only through that pitch's already-required bounded recovery; it is ownership state rather than an interval FIFO. Releases and safety transitions required by an owner that actually reached output are protected. This bound does not apply to externally delayed accepted work. Scheduler/OS lateness, unrelated stalls, and time inside a synchronous provider send may make several accepted logical boundaries overdue; those boundaries can drain close together physically after return without being reclassified as internal overflow. Playback and Analysis therefore retain their separated logical timestamps and identical filtering decisions. A smaller completed batch legitimately shortens the next adaptive constraint; pitch-local eligibility may still require a later boundary. Neither model is a second wall-clock output limiter.

The separate Interval polyphony state is default-off, session-only, and shared by the two note-interval modes without altering the ordinary queue-limit state. When enabled, its clamped value `1..128` is a hard maximum over actual NoteOn/NoteOff messages emitted at one logical interval. Protected releases are ordered ahead of attacks. The shared musical selector fills remaining capacity with deterministic attack candidates; every rejected attack suppresses its paired release. If protected releases alone exceed capacity, only the excess protected releases are rescheduled to the earliest following interval. Carried releases consume capacity where they are emitted and can displace every attack there; no other transition carries because of this limit. Adaptive timing counts the final emitted batch after this selection.

The Note start rate gate is distinct from the exact Events/sec service clock. It combines an exact rational virtual schedule with a bounded 50 ms batching tolerance and an exact half-open rolling one-second ledger. The tolerance preserves ordinary source batching and below-limit chords; it is fixed, so quiet time cannot enlarge it into stored credit. Every admitted velocity-positive NoteOn advances the rational schedule without an integer-microsecond approximation, while the ledger guarantees that no ordinary rolling second exceeds the selected maximum. Releases and non-note traffic do not consume this schedule; rejected starts enqueue rejected channel/key occurrences so FIFO-paired releases are suppressed, while admitted and unmatched releases pass. Simultaneous pressure uses the shared musical selector. Playback and Analysis share the pacer, segmented occurrence pool, and exclusion reasons.

The distinct Output rate gate limits total ordinary actual MIDI transmissions rather than NoteOn starts or simulated service. It combines the same exact rational schedule, bounded batching tolerance, and exact half-open rolling one-second ledger. Playback records successful calls at actual completion time; ideal nonblocking Analysis records the equivalent source-time completion. Below-limit demand remains transparent, the maximum setting preserves practical batches, quiet time saves no growing credit, and ordinary output never exceeds the selected rolling rate. No ordinary slowdown queue is involved, and rejected work is never retained for catch-up.

The Analysis graph divides each projected bucket count by that bucket's duration. It is deliberately not a sliding one-second estimator, so a 100 ms bucket can display more than the configured events/sec when the fixed 50 ms tolerance keeps a batch together. Deterministic light-to-dense evidence at 200/sec produced a 290/sec 100 ms bucket while every half-open rolling second remained at or below 200. Because dispatches are retained in the exact ledger for one second, the compensating underfilled bucket and the tolerated cluster can echo exactly one second later in rejected-event deltas. An experiment that removed tolerance from isolated ticks eliminated the graph rhythm but reduced a nonblocking live 426-message fixture to 314 messages because scheduler batching discarded matured service opportunities. The bounded tolerance and its truthful graph shape are therefore retained; the rhythm is neither ordinary cap excess nor a deferred catch-up queue.

Each source tick is planned as complete FIFO note occurrences. Controllers and source state consume ordinary capacity. Each admitted attack reserves one rolling-capacity slot for its later release; a same-tick attack/release pair reserves both messages immediately. The shared musical selector rejects least-important complete occurrences until actual messages plus outstanding release reservations fit. A paired release transfers its reservation to pending dispatch, so routine releases do not require ordinary excess. Immediate lifecycle cleanup bypasses the musical gate and is counted separately; rare required generated state that cannot obtain a slot is the only reported required-over-target path. Preserving-Seek retains reservations in dispatch order. Analysis runs the same selector and matcher with ideal source-time completions; provider blocking can still change later live decisions without creating a catch-up burst.

Boundaries are anchored to source time zero, and source events exactly on a boundary are considered first. Same-pitch NoteOns at the same absolute tick form one candidate whose strongest velocity wins. With a positive interval, a selected short note is held for at least one interval and retriggering a down pitch uses a preparatory release followed one boundary later by the new attack. At zero, each distinct source timestamp is a boundary; release and attack phases for the same pitch may share that timestamp but remain separate deterministic resolutions, preserving the one-transition-per-pitch rule without an artificial one-microsecond interval. Each resolution emits pitches in ascending order.

Selection is confined to the current logical batch. A candidate that loses there does not survive solely because interval pacing would otherwise place it at a later boundary. Within the batch, shared musical ranking preserves chord boundaries, strength, structural duration, and represented lanes with deterministic fairness and source order. Disabled-channel filters run before gate admission. Controllers, program changes, bend, pressure, SysEx, and system messages keep their established path. Simultaneous coalescing and interval rejection are counted separately from ordinary queue overflow.

If a live channel-disable safety operation silences the channel that supplied the currently sounding representative, an already selected occurrence on another enabled channel remains valid support. It is emitted as a replacement attack at the next legal boundary. A disabled pending representative is similarly replaced before emission; disabled occurrences themselves are never resurrected.

The gate deliberately has no generic simulated queue. Its Queue controls instead expose the stopped-only Interval polyphony state described above; Overflow stays unavailable because the interval policy is fixed and note-safe. Enabling/disabling a gate or changing structural gate controls retires and silences the scheduler, then restarts at the same transport position while preserving playing versus paused state. All pitch state is recreated from later eligible source events; no notes are chased or replayed.

Per-note **Maximum rate** is the one-transition interval frequency `1,000,000 / intervalMicroseconds`, not aggregate MIDI throughput. With adaptive scaling enabled, a multi-message boundary remains one burst and postpones the next note batch by the corresponding number of transition intervals. Effective speed uses a separate monotonic gate-resolution frontier. It advances after a boundary's complete output batch returns, including empty boundaries through sparse or filtered passages. It therefore stalls behind a blocked provider without depending on the non-monotonic source timestamps carried by individual transitions in one batch. The visible Timeline/output value keeps its established meaning: the source timestamp of the most recently sent event.

Lag retains event-level meaning. It is dispatch time minus that event's original source time, including deliberate boundary assignment, scheduler delay, and provider blocking. It does not estimate audible or rendering latency.

## Output boundaries

The default-off Output-paced timeline keeps one monotonic source clock separate from actual completed output. At a due timestamp, the entire same-time source batch may be admitted, but later timestamps do not mature while deterministic service or a synchronous provider call is outstanding. Completion shifts the source-clock anchor instead of enqueueing overdue future work, so there is no post-block source catch-up burst. Ordered preserving-Seek generations shift their own source anchors by the same service/provider duration. Analysis applies the equivalent deterministic transformation for simulated service only; native-provider blocking is measured live and is never predicted.

All outputs implement the same MIDI-output abstraction:

- WinMM packs short messages for `midiOutShortMsg` and keeps prepared `MIDIHDR`/SysEx memory alive through completion and unprepare.
- KDMAPI validates architecture and required exports, uses direct short-message submission, and supports prepared long messages only when the provider exposes the complete lifecycle.
- None implements allocation-free no-op open, send, reset, panic, and close operations while preserving logical dispatch statistics.

Detailed identity/error strings are built only on native failure. Stable module/device identity and architecture-dependent header sizes are cached outside the per-event success path.

Reset boundaries retire the worker before reset/panic whenever the active native call can return. Panic uses sustain-off, all-sound-off, and all-notes-off safety ordering. In-process managed code cannot forcibly cancel unmanaged code that never returns.

Play at a nonzero position and default Seek set one pending whole-state lookup. Default Pause also requires restoration because its reset/panic boundary clears controller state, but a paused worker emits nothing; Resume performs one chase before source dispatch. A chase send failure enters the ordinary playback-failure/panic path and later source messages cannot overtake it.

The default-off preserving Pause/Seek mode is captured as a session structural choice. Pause advances the transport base to the request instant, parks and acknowledges the same worker after its current logical dispatch boundary, and retains queue/model state and statistics without Reset or Panic. Seek stops new source admission, exposes the selected intended time immediately, drains every already accepted output decision, and dispatches one protected logical All Notes Off marker as channel CC123 messages. It then installs the newest target, runs state chase, and resumes ordinary target admission. Repeated requests retain every marker but suppress unadmitted output from superseded targets. Queue limits cannot discard the marker or evict retained work to make room for it. Per-note, delayed-release, attack-limit, finite-queue, unlimited-queue, and forward-only modes each resolve their already accepted state before the same marker boundary. Stop, replacement, disposal, timeout, and provider failure still use the hard cleanup path.

The Per-note gate now lives in the visible Rate model selector, alongside None and the ordinary service models. The main custom system menu retains forward-only admission, queue-age mode, state chase, and preserving Pause/Seek as less-frequent model choices; its Always on top command is a session preference. Every Analysis instance and the Channel Monitor append their own native Always on top command when their handle is created. Each command owns only that form's `TopMost` state, restores its check after handle recreation without duplicate entries, and is discarded with the form instance. About and Help belong to the main menu. F1 routes through the main form's normal WinForms key preprocessing to one reusable owned Help window, choosing a section from the active control without mutating engine or queue state. The guide is embedded as first-party text; no external file, browser, or native `WS_EX_CONTEXTHELP` style is required.

Application scaling is non-cumulative. The main window retains canonical margins, paddings, row heights, fonts, custom-painted metrics, responsive breakpoint, and minimum widths in 100% units. Analysis separately retains its client size, minimum, splitter position, command-bar geometry, report fonts, and graph-painting metrics. Channels retains its grid rows, headers, explanation, auto-fit rules, and either measured or user-resized column/window geometry. ## Analysis

Whole-file Analysis separates reusable file/resolution workload scanning from configuration-dependent queue projection. Workload counts and buckets can be reused when only service settings change; exact queue projections still recompute when their inputs change.

Every Analysis form owns an independent default-off **Show event counts** presentation flag. It transforms only the event panel's source and completed gate-output series from per-second rates to raw integer counts in the already accepted `BucketMicroseconds` interval. The native system-menu command invalidates the graph's static presentation layer and refreshes any inspection text without changing the immutable `WorkloadAnalysis`, cache key, analyzer generation, or pending calculation. Preview and completed results therefore switch immediately. Byte-rate and all non-event series remain untouched; exact inspection bounds clamp the last interval to `DurationMicroseconds`. Handle recreation rebuilds one checked command from the form-local flag, while a new form starts unchecked.

Each Analysis form also owns an independent default-off **Project forced overrides** flag. Enabling it snapshots all currently forced channel attributes after MainForm has selected the original or routed `MidiSong`; projection therefore follows Playback's route-then-override order. A bounded projection-only filtered song removes only source state that conflicts with the immutable snapshot. Forced messages bypass the ordinary queue and musical gates, as they do at Playback's ordered control boundary, and are added separately to gate-output buckets/counts; the report distinguishes generated forced messages from filtered competing source messages. The snapshot signature participates in local and shared cache keys, so a live override edit refreshes only enabled Analysis windows while disabled peers retain ordinary cached results. Handle recreation preserves the form-local check; closing discards it. No projection path mutates Playback, the route, or another Analysis instance.

For the first calculation in a window, the analyzer publishes one typed workload-only result after the reusable scan and summary complete. The callback exposes no mutable bucket arrays. The form generation-checks that preview independently from the final result and displays it only when no completed graph exists. Projection-only fields remain unavailable rather than appearing as zeros. Cancellation relabels a displayed preview as workload-only/cancelled, while stale generations, closed windows, and replaced files reject both preview and final publication. If queue projection then fails, the workload remains displayed and the report/status retain a concise exception explanation; failure before preview remains an honest error-only state.

Auto resolution is explicit state. Its visible label reports the resolution of the accepted graph, not a pending request. Cancellation retires the active/pending generation, and layout-only height changes do not re-arm the cancelled request.

Queue Projection drains accepted modeled work after the last arrival to calculate predicted output completion. Rejected events add no later service. Static Analysis intentionally excludes live Channel Monitor mutes and overrides.

When Per-note mode is selected, Analysis runs the same bounded `PerNoteIntervalGate` state machine over the immutable source events. The configuration-dependent pass emits non-note messages at their source times and selected note transitions at their gate boundaries. It records those logical emission times in a separate gate-output series while retaining the raw source-workload series. The gate interval participates in the Analysis cache key; a changed interval reruns only the gate projection when the file/resolution workload remains cached. Source-end releases may extend the graph past the file's source duration.

This mode does not display ordinary queue-pressure, overflow, or modeled queue-completion numbers: the gate temporarily disables the generic slowdown/queue model. The projection uses source-file events and their source order, not live Channel Monitor mutes or overrides. It does not predict native driver delays, synthesizer rendering, or audible tails. An initial workload preview remains explicitly pending until the gate pass finishes; cancellation and stale-generation checks use the same Analysis publication boundary as ordinary queue projections.

## UI publication cadence

The main form samples the newest immutable playback/loading state on an approximately 16 ms presentation heartbeat and changes displayed values only when content differs. Loading memory is sampled about once per second. Its fixed-height double-buffered status surface avoids parent layout and partial-text painting on each update.

The Channel Monitor’s scheduler-side state is fixed-size and allocation-conscious. The UI copies one 16-channel snapshot on its presentation cadence and updates only changed cells. Closing the monitor removes the presentation cost; routing/override state remains engine-owned when required.

The main Processing-model numeric fields reuse the Channel Monitor's scrub/typing state machine in numeric-only mode. That mode has no forced/historical/Auto semantics. It retains exact `int`-range values through the current 100,000,000-bit/s maximum, emits a setting change only after a real scrub step or committed edit, and keeps the existing live next-service boundary. Compact statistic slashes use explicitly measured narrow visual spacing because the custom Consolas readout font renders Unicode thin spaces at ordinary monospaced width.

Build 38 added an optional numeric scrub mapping to the shared editor without changing its Channel Monitor path. A drag is measured from its initial exact integer value; the processing field converts pointer displacement through the active slider scale and adds only the mapped delta. This avoids snapping a typed value to a nearby slider tick. Shift switches to one numeric unit per pixel, and the drag remainder is rebased on modifier changes.

Build 39 gives Queue limit its own continuous displacement curve. Below roughly 500 the response stays close to one step per four pixels; larger values accelerate smoothly so a large limit is practical to adjust. Shift remains a fine one-step-per-two-pixels mode. Both curves are derived from the drag's exact starting integer and signed displacement, so reversing to the start restores that integer. The numeric-only editor centers its glyphs and measures their actual typographic width plus border clearance. The Channel Monitor editor retains its separate right-aligned override presentation and scrub contract.

The main fields measure the actual displayed text using `TextRenderer` with `NoPadding | SingleLine`, add a font-scaled inset, and resize with content. A field does not shrink while text is actively being typed; it settles after the edit. Native text-box height and its containing row are measured after font changes before recomputing form constraints. This keeps default and compact geometry content-driven rather than assigning one width for each mode.

Analysis recomputation debounce, delayed busy indication, effective-speed smoothing, and native playback timing remain separate mechanisms because they serve different semantics.
