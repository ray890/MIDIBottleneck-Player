# Build 31

Original handoff date: 2026-09-23 7:22 AM EDT

## Player changes

- Finite queue statistics now show the real eligible MIDI backlog that builds while an output call is blocked, even with simulated slowdown off.
- Added **Apply queue limit without slowdown**, checked by default in the window menu. It applies virtual queue pressure and forward-only Drop newest or complete-note rejection without deliberately delaying accepted MIDI.
- Separates the actual unsent backlog from the virtual pressure display and excludes muted/overridden source events from both admission and statistics.
- Static Analysis uses the same forward-drop decisions and explains that it does not predict delay inside a MIDI driver or synthesizer.

## Performance findings

- Bounded injected-adapter measurements found no stable application-side KDMAPI penalty relative to WinMM; no speculative native-path change was made.
- Large-file preflight and production parsing remain separate costs by design: ordinary files bypass preflight, while warning-sized files receive an allocation-light exact scan before parsing.

## Verification

- Focused tests cover blocked finite output, channel/override filtering, complete-note protection, Reset Statistics, transport boundaries, Analysis parity, and system-menu state.
- Complete x86/x64 totals and release hashes are recorded in the Build 31 checkpoint.

## Known limitations

- Whole-state Play/Seek chase remains deferred. The existing one-attribute Channel Monitor source chase is unchanged.
- Drop oldest and clear/catch-up require Simulate slowdown because a forward-only model cannot retract MIDI already sent.
