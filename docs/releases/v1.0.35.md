# Build 35 — Oldest complete-note overflow

Original handoff date: 2026-09-24 EDT

## Player changes

- Added **Drop oldest complete note** for a finite queue with simulated slowdown. It removes the oldest queued note that has not begun service, together with its matching release if that release is already waiting. A later matching release is suppressed when it arrives.
- Kept notes already in service safe from removal. Releases and note-silencing controls may temporarily exceed the configured queue limit; if there is no old unsent note to remove, an ordinary new event is rejected and counted clearly.
- Kept the original **Drop oldest** single-event choice. The new choice is unavailable for forward-only queue limiting without simulated slowdown because MIDI already sent cannot be taken back.
- Made Analysis project the same source-file queue decisions. Live channel mutes and forced overrides remain outside static Analysis.

## Verification

- Deterministic x86 and x64 tests cover note pairing, overlapping pitches, velocity-zero releases, protected traffic, filtering, policy changes, lifecycle boundaries, output failure, and Playback/Analysis agreement. A bounded dense-queue benchmark measures time, collections, and retained index memory.

## Known limitations

- The queue limit is a soft ceiling for required releases and note-silencing controls. It is not a promise that a synthesizer finishes sounding at the modeled completion time.
