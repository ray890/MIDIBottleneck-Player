# Build 44 — Musical traffic control, track routing, and trustworthy shutdown verification

Original handoff date: 2026-09-27 EDT
Published version: `1.0.44.0`

Build 44 is the largest MIDIBottleneck Player update so far. It adds several distinct ways to control dense MIDI, a complete session track-routing workflow for constrained hardware, bounded RIFF/RMID compatibility, new Analysis projections, three borderless-window presentations, and a restored release gate that watches for native Windows failure dialogs and crash-reporting processes after the managed tests finish.

## Rate models and musical traffic control

### Delayed NoteOff

- Added **Delayed NoteOff** as a standalone Rate model for reducing repeated same-pitch traffic without creating stacked voices.
- One pitch has one global owner across tracks and channels. The selected duration sets the minimum hold and retrigger boundary; a short recovery period can retain at most one musically selected replacement.
- Corrected an occasional melody loss during that recovery. The correction remains bounded to one candidate per pitch and keeps every emitted attack paired with the proper release.
- A zero interval adds no artificial time delay or quantization. Only intentional ownership, pairing, and simultaneous-transition rules remain.

### Note start rate gate

- Added a separate **Note start rate gate**. It limits admitted velocity-positive NoteOn starts only; releases, controllers, state, and safety messages do not consume this particular limit.
- Exact fractional pacing, a short fixed batch-preservation tolerance, and an exact rolling one-second ceiling keep below-limit passages and practical maximum-rate chords transparent.
- Quiet passages do not save burst credit. Rejected attacks stay at their source positions, their paired releases remain suppressed, and nothing is queued for later catch-up.
- When simultaneous starts compete for capacity, Playback and Analysis use the same deterministic musical ranking.

### Output rate gate

- Added a distinct **Output rate gate** with the visible value **Maximum output rate**.
- It limits ordinary messages actually transmitted, including controllers and source state. An admitted attack reserves capacity for its later release, so routine release protection cannot conceal ordinary over-limit output.
- Stop, Panic, output replacement, disposal, timeout, and failure cleanup remain immediate safety boundaries and are counted separately.
- Live Playback uses the completion time of the real output call. Analysis uses equivalent deterministic logical timing, so an unpredictable blocking provider can legitimately change later live decisions without causing a catch-up burst.
- Measurement confirmed that the brief load-transition peak visible in short Analysis graph buckets is not a rolling-ceiling violation. The associated one-second rejected-count rhythm is the exact expiry echo of a preserved batch. Removing the bounded tolerance caused severe live underuse, so the truthful rhythm was retained.

### Other interval and timeline controls

- Added default-off **Scale note interval by note traffic** for Per-note and Delayed NoteOff. A batch containing more actual note transitions proportionally postpones the next note batch.
- Added a separate default-off **Interval polyphony limit** from 1–128 messages per logical interval. Required releases outrank new attacks; only excess protected releases can carry forward.
- Bounded internally paced note work to the source batch currently being resolved. Rejected work does not become an unbounded hidden queue.
- Added a default-off, session-only **Output-paced timeline**. Source time waits for a due timestamp or same-time batch to finish deterministic service and synchronous output acceptance, preventing future timestamps from accumulating into a post-block burst.

## Queue, overflow, Pause, and Seek

- Added **Drop background notes** as a finite event-count overflow policy. It removes complete unsent note occurrences while preserving prominent chord boundaries, represented tracks or lanes, percussion fairness, and attack/release safety.
- The numeric event-count Queue limit can now be edited during ordinary finite-queue playback. Increases affect the next admission; decreases do not retract an event already in service or purge previously accepted ordered work.
- Queue-now, maximum occupancy, and age statistics now include due work behind a blocked synchronous send while excluding filtered, coalesced, and deliberately future work.
- Added default-off **Preserve playback queue on Pause and Seek**. Pause parks the same worker without resetting the queue or statistics. Seek drains admitted decisions, sends a protected 16-channel All Notes Off boundary, then performs target chase and output.
- Repeated preserving Seeks keep their ordered boundaries. Stop, output replacement, failure, timeout, and disposal remain hard cleanup boundaries.

## Track routing for constrained MIDI hardware

- Added a complete stopped-only, session-only **Track routing…** editor.
- The editor lists each MIDI track and channel combination; one MIDI track can appear more than once when it uses multiple channels.
- It shows usable destinations, melodic capacity, percussion policy, automatic tier, representative instruments, warnings, errors, manual corrections, and a destination-grouped complete preview before anything is applied.
- Used output-channel captions are bolded from the compiled result. Patch tooltips reuse the same canonical General MIDI names as Channels and include the 1-based Program number.
- Manual destinations replace automatic choices within the selected capacity rather than silently adding an extra destination.
- Unresolved plans cannot be applied. GM-family, Aggressive, manual, or omitted-lane plans require explicit lossy confirmation.

### Destination state and Aggressive selection

- Bank, Program, and other channel state is associated with the source channel it governs even when format-1 MIDI stores state and notes in different tracks.
- Note-empty initialized channels are excluded from musical destination selection.
- Each destination receives one deterministic, deduplicated Bank/Program timeline. Clean non-overlapping parts can hand instruments off; conflicting changes during real overlap yield to the selected representative instead of racing on the hardware.
- Aggressive routing now chooses representatives across the whole song. It balances musical importance, independent overlapping roles, state conflicts, instrument-family coverage, and the cost of retimbring or omission.
- A weaker lane is omitted only when every merge is more destructive. Its row and preview report the exact omitted note-start count, and the complete lossy plan still requires confirmation.
- Playback, Analysis, chase, Channels, filtering, forced overrides, note ownership, and statistics all consume the same immutable compiled routed view while the original MIDI remains unchanged.

### Large-file routing

- Large-file preflight now includes bounded retained-name, routing-plan, occurrence-summary, generated-state, and routed-index allowances.
- The preview reports routed entries, shared destinations, retimbrance, omissions, generated destination state, and the exact final routed-view message total.
- Routing does not create a second unbounded MIDI copy merely to calculate the preview.

## MIDI file compatibility

- Added bounded RIFF/RMID loading and `.rmi` file selection. The RIFF form, chunk sizes, odd-byte padding, `data` boundary, and enclosed `MThd` stream are validated before normal parsing.
- Preflight and both parser representations use the same bounded source view rather than copying an unbounded payload.
- Added one narrow compatibility repair for a channel message immediately after metadata when the most recent channel status is the only valid interpretation. Every repair is counted and disclosed; ambiguous or unrelated malformed input remains rejected.

## Analysis and Channel Monitor

- Added independent, default-off **Show event counts** to each Analysis window. It changes accepted graph and inspection data from events per second to integer events in the displayed interval without rerunning Analysis.
- Added independent, default-off **Project forced overrides** to each Analysis window. It snapshots current destination-channel forces after Track routing, separates generated forced messages from filtered source state, refreshes enabled windows when overrides change, and never sends MIDI or changes Playback.
- Spacebar Pause/Resume now follows the active Analysis window rather than pointer location while preserving normal behavior for text editing, open dropdowns, and modal dialogs.
- Analysis windows and the Channel Monitor each have independent session-only **Always on top** commands.
- Channel 10 now uses effective Bank and Program state to show recognized GM2, common GS, and XG drum-kit names while retaining the numeric Program. Unknown combinations use an honest numbered drum-kit fallback; melodic channels keep General MIDI instrument names.
- Corrected a forced-override acknowledgement race: returning a value to Auto immediately after its send now preserves the last transmitted value as gray historical provenance until real source state returns.

## Main-window and presentation refinements

- Added a default-off, session-only **Borderless main window** with three styles:
  - **Classic strip** — a compact dedicated title strip;
  - **Integrated header** — the system menu and window controls share the File and output row;
  - **Auto-hide overlay** — controls appear while the pointer is inside the main window without shifting or resizing content.
- Invisible edge and corner presses that begin over child controls are forwarded into native Windows resizing without drawing a border.
- All styles retain Alt+Space, keyboard-accessible controls, native moving and snapping, taskbar/Alt-Tab identity, maximize/restore behavior, scaling, and exact native-frame restoration.
- Improved the grouped Rate popup for rapid mouse/keyboard activation, visible nonselectable headings, correct native selection behavior, measured text width, and 50%–200% scaling.
- Corrected compact Queue/Overflow geometry, statistic-value priority, timeline measurement, 50% Open MIDI sizing, scale restoration, output-caption alignment, and system-derived enabled/disabled numeric-field colors.
- Main, Analysis, and Channels scaling remains non-cumulative: returning to 100% restores canonical geometry and fonts.

## Trustworthy shutdown verification

Build 43’s original release testing incorrectly treated managed success, empty error output, and no surviving process as sufficient proof of clean shutdown. The user-visible `0xC0020001` dialog was later reproduced in the old synthetic test lifecycle and captured as a second-chance `0xC000041D` failure on the main UI thread.

Build 44 restores a trustworthy gate:

- Ordinary deterministic UI tests now run inside a real `Application.Run` message loop.
- A native monitor independently watches top-level windows and descendant error-reporting processes while the test runs and for five seconds after exit.
- Controlled x86 and x64 fixtures prove both detector channels can recognize an expected suspicious window and descendant process.
- Managed assertions, process exit, error output, native-window teardown, and descendant-process teardown are recorded as separate results.
- The final complete suites passed **120/120 tests on x86** and **120/120 tests on x64**.
- Both packaged players separately passed monitored launch/close with exit code 0, empty error output, and no suspicious native window or descendant process.

The failure was confined to the former synthetic test harness. No player-side error suppression, forced process termination, or machine-wide diagnostic setting was added.

## Important retained limits and future work

- Native MIDI provider calls remain synchronous. The player cannot safely force-stop a third-party provider that never returns.
- Borderless pointer resizing uses the real child-control/native-resize path and passed automated coordinate and lifecycle tests; physical edge feel can still vary with hardware, scaling, and Windows input settings.
- Analysis is deterministic and cannot predict synthesizer voice stealing, audible release tails, or unpredictable native-provider blocking.
- **Drop background notes** remains unavailable with waiting-time queue limiting because dropping a newer weak note does not necessarily repair an already overdue oldest item.
- Track-routing plans and all new presentation/transport choices are session-only.
- Automatic generated routing schedules, broader forced-override systems or presets, compositor synchronization, producer/consumer output separation, helper-process MIDI isolation, and portability remain future product or rewrite decisions. They are not defects in Build 44.
