# Build 42 — Queue waiting time and application scaling

Original handoff date: 2026-09-26 EDT

## Player changes

- The grouped **Rate model** selector now exposes **Simulated slowdown** and **Bandwidth / note gating** as static labels, not selectable or accessible model items.
- Processing time, MIDI bitrate, Events/sec, and Per-note interval each remember their own value. **None** remains genuinely immediate.
- A Per-note interval of zero now resolves at the MIDI's distinct source timestamps without substituting a hidden one-microsecond interval.
- The default-off **Limit queue by waiting time (µs)** command can limit pending work by the age of its oldest eligible unsent event. Playback and Analysis use the same strict boundary and overflow decisions.
- The main, Analysis, and Channels windows can be scaled to 50%, 75%, 100%, 125%, 150%, or 200% for the current session. Scaling is non-cumulative and returning to 100% restores each established layout.
- Corrected an intermittent x86 window-opening failure in the native scale submenu when Windows returned a popup-menu handle with its high bit set.

## Queue and presentation behavior

- Waiting-time mode permits an event exactly at the limit and starts overflow only above it. It offers Drop oldest, soft **Drop oldest complete note**, and clear/catch-up; policies that cannot repair an overdue head are hidden.
- Waiting-time mode and forward-only admission are mutually exclusive. Muted or override-suppressed source events do not consume waiting pressure or become queue drops.
- Main scaling covers compact/default layouts, hidden sections, fonts, Statistics, and the timeline. Analysis scales its command bar, split report/graph, inspection area, and graph painting. Channels scales its grid and editor while preserving auto-fit or manual window/column sizing.

## Verification

- Focused deterministic tests cover the Rate selector's static accessibility labels, independent values, zero-gate output, queue-age policies and lifecycle behavior, Playback/Analysis parity, filtered blocked output, statistics reset, repeated scale cycling across all three windows, responsive transitions, hidden sections, repeated form/handle lifecycles, and exact 100% restoration.
- Full deterministic x86/x64 totals and release hashes are recorded in the private checkpoint.

## Known limitations

- Queue age is a scheduler model based on logical MIDI time. Static Analysis does not predict buffering or blocking inside a native provider or synthesizer.
- Complete-note waiting-time eviction is deliberately soft when a protected release or safety message is the overdue head.
- Very large companion-window scales clamp to the current monitor's working area.
