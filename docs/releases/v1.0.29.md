# Build 29

Original handoff date: 2026-09-22 8:10 PM EDT

## Player changes

- Keeps ordinary MIDI files on the existing one-pass direct compact parser.
- Inspects unusually large files with a cancellable, allocation-light SMF grammar scan before creating event stores.
- Reports exact dispatchable-event counts and storage-aware retained/peak memory projections before a risky load.
- Uses stronger 32-bit guidance and lets the user Continue or Cancel without stale load publication.
- Preserves monotonic loading progress across inspection, confirmation, and parsing.

## Memory model

- x86 inspects files at least 15 MiB and warns at a projected 1 GiB retained/conservative-peak boundary.
- x64 inspects files at least 63 MiB and warns at a projected 4 GiB boundary.
- Estimates include compact final and provisional records, segmented payloads, tempo changes, source-value histories, segment/reference overhead, and bounded merge workspace.
- File size decides only whether exact inspection is warranted; displayed estimates come from parsed SMF counts.

## Verification

- Count-only and production-parser results were compared across running status, one/two-byte messages, meta/tempo events, F0/F7 payloads, multiple tracks, malformed/truncated data, cancellation, source-value expansion, and segment boundaries.
- Continue, Cancel, stale-generation, ordinary-file bypass, monotonic progress, and architecture-specific classification were verified deterministically.
- A bounded 250,000-event scan allocated roughly 74 KiB and caused no Gen0 collection on either architecture.
- The complete deterministic suite passed 96/96 on x86 and 96/96 on x64.

## Known limitations

- Projections cannot guarantee successful allocation because CLR fragmentation, other process memory, commit availability, and paging are external to the SMF counts.
- Exact preflight necessarily reads qualifying large files once before the normal parser reads them again.
