# Build 38 — Main numeric refinement

Original handoff date: 2026-09-25 EDT

## Player changes

- Processing value and Queue limit now size themselves to the number shown, making short values more compact while keeping long values readable. Both the standard and compact layouts were remeasured for alignment.
- Dragging the processing value follows the selected slider's scale. Small event rates change more gently; high rates can be reached without an excessively long drag. Shift adjusts one displayed unit per pixel.
- Scrubbing starts from the exact typed value. Clicking, moving less than the drag threshold, or reversing a drag does not round that value to a slider step. Queue-limit scrubbing and Channel Monitor override behavior are unchanged.

## Project and documentation changes

- Clarified the drag interaction in the user and technical guides. Recorded a measured design for possible future UI scaling, without adding an incomplete scale mode.
- Added separate future-design notes for rate-model presentation, delayed note releases, and a real-time event-rate limit that would reject excess notes.

## Verification

- Focused tests exercise compact and standard geometry, displayed and maximum values, typing and settling, enlarged fonts, rate-model drag scales, and Shift behavior. Complete x86/x64 deterministic totals and exact executable hashes are retained in the private release checkpoint.

## Known limitations

- Application-relative UI scaling remains a future feature. The accepted 100% default and compact layouts continue to use native Windows DPI behavior.
