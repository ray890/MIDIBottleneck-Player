# Build 28

Original handoff date: 2026-09-22 12:50 PM EDT

## Player changes

- Streams each declared MIDI track through a bounded reader instead of allocating a complete track byte array.
- Parses into compact segmented provisional records and performs stable timestamped merge directly into the final compact store.
- Segments tempo changes and one-value source-chase histories, including logarithmic lookup across segment boundaries.
- Removes the separate post-merge conversion and progressively releases consumed provisional records, payloads, and tempo data.
- Uses 2,048-record/80 KiB event segments to avoid retaining discarded provisional segments on the large-object heap.

## Memory and performance

- The final record remains 40 bytes; no per-event object graph exists in production loading.
- On the bounded one-million-event fixture, observed peak managed memory fell from Build 27's roughly 91–118 MB range to about 60–66 MB.
- Retained private delta measured about 42.7 MB on x86 and 40.5 MB on x64. Analysis and immediate None playback produced no Gen0 collections.

## Configuration and packaging

- The allocation audit found no supported production path requiring a greater-than-2-GB CLR array.
- Both x86 and x64 packages now contain only the executable, README, and GPL license; no configuration sidecar is required.

## Verification

- Direct and legacy-reference parsing were compared for ordering, exact timestamps, payload hashes, running status, simultaneous cross-track tempo changes, malformed input, segment boundaries, source-value lookup, and cancellation.
- The complete deterministic suite passed 95/95 on x86 and 95/95 on x64.

## Known limitations

- Total loading remains limited by available address space/commit and an explicit 2,147,483,647-event indexed identity.
- A proactive count/memory preflight remains deferred because an exact first pass would read very large files twice.
- Static Analysis still excludes live Channel Monitor filtering and the live per-note interval gate.
