## XP capability report: what each measurement tells us

From Milestone 4 the XP self-test also writes a capability report (`capability-report.txt`, and the same values after the parity results in `selftest-result.txt`). These are measurements, not pass/fail checks. They decide how later milestones run on this machine.

- **Processor flags (SSE, SSE2, ...).** Whether a processor has SSE2 and any newer instruction set. Since prompt 009 the XP release build is `/arch:IA32` (no SSE2 needed); the flag only decides whether the SSE2 test-comparison variant of the self-test can run.
- **Performance counter frequency and stability.** The playback clock (Milestone 5) converts counter ticks to microseconds. Backward steps or drift against the tick count would mean an unreliable clock on this hardware.
- **`Sleep(1)` with and without `timeBeginPeriod(1)`; waitable timers.** How finely the playback worker can wait. v1 waits with a high-resolution waitable timer and spins for the last ~200 µs; XP has no high-resolution timer, so the coarser figures here set how much spinning (CPU use) XP playback needs.
- **Threads, priority, mutex, condition variable, 64-bit atomics.** The engine uses one worker thread at above-normal priority, a lock, wake-ups and atomic counters. The round-trip latency is the cost of every wake-up between the user interface and the worker.
- **Memory (largest block, total address space, commit speed, large-address-aware).** The largest MIDI file the XP build can hold, and whether marking the executable large-address-aware would raise that limit on this machine.
- **Files (file system, files over 4 GB, positioned reads past 2 GB and 4 GB, read speed).** Whether very large MIDI files can be opened at all from this disk (FAT32 cannot hold files of 4 GB or more), and how fast loading can be.
- **MIDI devices and OmniMIDI/KDMAPI presence.** Which outputs the WinMM backend will list, and whether the KDMAPI backend could find a provider. Nothing is opened, loaded or played.
- **Fonts, DPI, screen size, visual styles, layered windows.** What the Milestone 6 user interface can rely on: v1's fonts (Segoe UI or Tahoma, Consolas or Lucida Console), scaling, themed controls, and translucent overlay windows.
