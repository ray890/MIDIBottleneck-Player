# Rules that classify the differences between v1.0.44's recorded output and v2's output.
# Read by midibn-parity and v2-xp-selftest (and midibn-engine-harness --rules). Every rule belongs to an entry
# of the improvement register, v2/docs/DIFFERENCES_FROM_V1.md (the DD-NNN id). A difference that no rule
# explains fails; a rule whose targets were compared and that no longer matches anything also fails.
# Grammar: v2/harness/TRACE_FORMAT.md, "Difference rules". Short form, one rule per line:
#   trace  DD-NNN <trace glob> /<v1 line regex>/ /<v2 line regex>/   a line that differs at the same position
#                                                                  (${N} in the v2 regex = text of group N of the v1 regex)
#   insert DD-NNN <trace glob> /<v2 line regex>/                     a line v2 has and v1 does not
#   delete DD-NNN <trace glob> /<v1 line regex>/                     a line v1 has and v2 no longer has
#   engine DD-NNN <scenario glob>@<fixture glob> normalize=<name> [pin=<fixture>:<lines>,...] [files=out|sched|both]
#   engine DD-NNN <scenario glob>@<fixture glob> explained [files=out|sched|both]
# Regular expressions are ECMAScript and must match the whole line. Globs: * and ? and comma-separated alternatives.
format 1

# DD-001: SysEx messages of 1 to 3 bytes keep their bytes (v1 reads them back as zeros).
# Load/index traces: the line is the same except that the data field, all zeros in v1, holds the file's bytes in v2.
trace DD-001 sysex-short-mid.trace,sysex-variants-mid.trace /(e \d+ \d+ \d+ \d+ SystemExclusive -1 (?:F0|F7) )([123]) (?:00)+/ /${1}${2} [0-9A-F]{2,6}/
# Engine recordings: v2's SEND line of a 1-3 byte SysEx is mapped to v1's zeros before hashing; the number of
# mapped recording lines is pinned per fixture (over all 172 scenarios). The pins count v2's lines; v1 has fewer (1976 and 679) because in the
# DD-006 scenario v2 plays on after the Resume where v1 froze (9 and 2 more SysEx lines); make-engine-expected.ps1 checks v1 against this:
# v1-pin: sysex-short:1976,sysex-variants:679
engine DD-001 *@sysex-short,sysex-variants normalize=short-sysex-zeroed pin=sysex-short:1985,sysex-variants:681

# DD-020: event times from exact integer arithmetic. v1's decimal rounding noise made it one microsecond low where the
# true time is exactly halfway between two microseconds, so a changed time is always v1's plus one.
# Load/index traces: the tempo-map time and the event time of the affected lines.
trace DD-020 decimal-halfway-mid.trace,tempo-changes-mid.trace /t (\d+) (\d+) (\d+) (\d+) (\d+)/ /t ${1} ${2+1} ${3} ${4} ${5}/
trace DD-020 decimal-halfway-mid.trace,tempo-changes-mid.trace /e (\d+) (\d+) (\d+) (\d+) (.*)/ /e ${1} ${2} ${3+1} ${4} ${5}/
# The large fixture's summary digest (it covers the event times).
trace DD-020 large-8m-mid.summary.trace /digest sha256 [0-9A-F]{64}/ /digest sha256 [0-9A-F]{64}/
# Analysis results computed on those two fixtures (digest of the buckets or of the emitted messages).
trace DD-020 models/analysis.trace /= (buckets|emitted) (\d+) [0-9a-f]{16} (.*)/ /= ${1} ${2} [0-9a-f]{16} .*/
# Engine recordings of the two fixtures: sends and wake-ups move by that microsecond.
engine DD-020 *@decimal-halfway,tempo-changes explained

# DD-024: the large-file memory estimate counts what v2 really stores (24-byte events, no .NET object headers).
trace DD-024 *-mid.trace,*-rmi.trace,large-8m-mid.summary.trace /estimate ptr(\d) retained .*/ /estimate ptr${1} retained .*/
