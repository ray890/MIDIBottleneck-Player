# MIDIBottleneck Player v2 - real-time engine scenarios (Milestone 5 exit test).
#
# Read by v1-realtime.exe (v2/harness/v1-reference/realtime) and
# midibn-engine-realtime.exe (v2/tools/engine_realtime_main.cpp), driven by
# v2/tools/engine-properties.ps1. Same grammar as engine-scenarios.txt
# (v2/harness/ENGINE_SCENARIOS.md) with two differences:
#   * every time is REAL elapsed microseconds since the run began ("N/M" is
#     still the fraction N/M of max(1000, song duration)), and the commands are
#     applied by a control thread at those wall-clock offsets;
#   * "route" is not supported.
# The "describe" line of each scenario carries machine-read tags before a "|":
#   fixture=NAME[,NAME]   fixtures (stems in v2/harness/fixtures) the scenario runs on
#   class=exact|prop      exact: no real-time-dependent decision (v1 decides only on
#                         song time), so the sent sequence must be identical between
#                         runs, programs and architectures; prop: property checks only
#   ends=N                PlaybackEnded events expected
# The rules behind the scenarios are cited in v2/docs/ENGINE_PROPERTY_CHECKS.md.
# Scenarios are added, not edited, once results exist.
#
# Fixtures (v2/harness/fixtures): models-dense is 9,166 events in 1.41 s (two
# bursts of about 4,500 events within 100 ms, NoteOn/NoteOff/controllers);
# index-chase-rich is 1,255 controller/program/bend/aftertouch events in 3.16 s
# on all 16 channels (no NoteOff); f1-v1-test-midi is 6 events in 1.5 s;
# f0-all-message-types, sysex-short and sysex-variants are under 0.1 s.
format 1

# MainForm's configuration for a rate model on the Drop path (ENGINE_SCENARIOS.md section 5).
profile drop-300us-limit24
  set simulate-slowdown on
  service processing-time 300 31250 10000
  set queue-length-limit 24
end-profile
