# Opportunities

These are deliberately deferred observations, not commitments for the current release.

- **Segmented or compact event storage** — Could reduce the very high memory cost of hundreds-of-millions-event files and remove the final contiguous reference-array ceiling. Evidence: the successfully loaded 227,108,447-event file used roughly 23 GB, while larger inputs approach the x64 array boundary. Benefit is high for extreme files; risk/scope is high because parsing, binary search, scheduler cursors, seeking, and Analysis all assume indexed contiguous storage.
- **Genuine display-compositor pacing** — Could potentially align purely visual refresh with presentation timing on high-refresh monitors. The present 16 ms timer plus coalesced custom painting is responsive; loading now shares that heartbeat and measures about 40 Hz under the exercised message-loop load. A monitor-derived timer would not be true synchronization. Benefit is uncertain; risk/scope is medium to high because a correct solution would need a different rendering/presentation integration.
- **Extreme-load post-publication pause attribution** — The user observed an approximately-30-second UI pause after one roughly-50-GB Red Zone load. The normal completion path performs only small UI/property updates, so plausible causes include managed collection/finalization, paging, or release of enormous parser temporaries rather than the selected MIDI provider. Benefit of attribution is high for extreme files; scope/risk is high because it needs isolated ETW/GC/commit measurements on a memory-saturated host and must not become a routine giant-file test.
- **Interruptible native-output isolation** — A helper-process boundary could allow the application to recover from a MIDI driver call that never returns. Current bounded scheduler checks cannot interrupt unmanaged code already executing. Benefit is improved resilience to defective drivers; risk/scope is high because it changes output lifetime, IPC, timing, and SysEx buffer ownership.
- **Measured ordered-output producer/consumer boundary** — A dedicated ordered submission stage could potentially separate scheduler work from provider-call latency, but it would redefine backlog, lag, cancellation, finite-buffer pressure, and Stop/Seek reclamation semantics. Current deterministic adapter overhead is already near parity, and native providers may not be thread-safe. Benefit is therefore unproven; risk/scope is high and requires provider-specific measurement and a separate design pass.
- **Drop oldest complete note** — An exact bounded implementation needs an intrusive pending-queue node for each admitted event, plus per-channel/key occurrence lists that can unlink both members of the oldest safe note in amortized O(1). The current `Queue<int>` cannot remove an arbitrary pending NoteOn/NoteOff pair without a linear scan or full rebuild. It must also define what happens when the NoteOff has not arrived, when one member is in service, and across a live policy change. Benefit is useful musical overflow experimentation; risk/scope is medium-high because playback and Analysis must share identical pairing and removal semantics without large transient allocations.
- **Virtual finite capacity without applied slowdown** — A coherent no-delay design should explicitly separate a shadow modeled-service queue from the real unsent output queue. Forward-only policies such as Drop newest and Drop incoming complete notes can reject the current arrival honestly, but Drop oldest cannot retract an event already sent and Clear cannot clear already-sent output. One possible restricted mode would allow only forward-dropping policies while displaying modeled pressure as virtual; a general mode would require an ordered producer/consumer scheduler and new lag/cancellation semantics. Benefit is clearer workload experimentation; risk/scope is high and should be decided as a separate scheduler/UI contract.
- **MIDI state chase at mid-song starts** — A standards-preserving chase would reconstruct the latest bank/program, controller, bend/pressure, RPN/NRPN and completed SysEx state before admitting notes at the target. The bounded LBSFS prefix proves that direct starts currently bypass meaningful CC7 and other state, but CC7 does not establish the separate scheduler-lag symptom. Use equivalent-interval None/WinMM/KDMAPI measurements first to distinguish scheduler timing from provider/synthesizer behavior. Benefit is repeatable direct-seek sound; risk/scope is medium-high because controller ordering, resets, incomplete SysEx, sustain and intentionally clean starts need an explicit product contract.
